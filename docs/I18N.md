# Internationalization

**i18n status: Applies - deferred to the first release that renders this measurement for
a reader who is not reading the code.**

Reason: the internationalization standard is about civic data presented to the public,
and this project's output today is not that. It produces one JSON artifact and one
generated Markdown document, both aimed at somebody working directly with California
utility and wildfire data, and both read next to the source that produced them. There is
no user interface, no served page, and no form. Localizing a technical measurement
document that nobody outside that audience reads would be motion rather than access.

The trigger is a real one and not a date: if this measurement is ever rendered as a page
intended for a general reader, the audience changes and the standard binds immediately.
Recording it that way rather than declaring the standard inapplicable, because the
subject matter is squarely civic and the exemption is about the current form of the
output, not about the topic.

## What is done

Decided in `docs/adr/0016`, which amends this declaration.

- **The renderer's words are extracted into a catalog.** Every string the generated
  document prints on its own account lives in
  `src/wildfire_service_territory_overlap/catalog.py`, as a declared, ordered mapping
  from a stable key to one edition's string.
  `src/wildfire_service_territory_overlap/report.py` takes a catalog as a parameter of
  `render`, defaulting to the English one, and carries no prose of its own. A test
  parses the renderer and fails if a string a reader could read is left inline in it,
  and that test has been watched refuse a string put back on purpose.
- **A second edition is checked for shape before it can be used.**
  `catalog.translation` refuses an edition that is missing a key, carries a key nothing
  renders, holds an empty string, or changes the placeholder fields inside an entry.
  The last one matters most: `str.format` ignores a keyword nothing uses, so an entry
  that drops `{fire_records}` would render the sentence without the number and raise
  nothing.
- **Numbers are formatted once, for the artifact, not per edition.** `report.pct`,
  `report.count` and `report.span` take no catalog and cannot be given one, and no
  catalog entry may carry a format spec. Both facts are held by tests. A test also
  renders the whole report under a second catalog holding the same keys and different
  strings, and asserts that every figure, both ends of every interval and the order of
  every row come out identical.
- **The determinism gate is unchanged and covers every edition.** The same artifact and
  the same catalog produce the same bytes. Extracting the strings moved the English
  output by nothing: `published/REPORT.md` still renders exactly from
  `published/measurements.json`.

## What is not done

- **No Spanish catalog exists.** Nothing here is a Spanish edition, and the work left
  before one could exist is not code. A translation needs review by somebody who reads
  Spanish, sitting with the measurements and checking that each string says what the
  number beside it means. A generated translation is not a reviewed catalog and
  `docs/adr/0016` refuses to publish one as though it were.
- **The artifact's own strings are still English and still inline.** Row labels,
  measurement notes, the county note and the type-field note are written in the modules
  that measure, land in `measurements.json`, and are read straight out of it by the
  renderer. They are data in the artifact rather than prose in the renderer, and
  translating them would give each language its own `measurements.json`, which is the
  opposite of both editions rendering from one artifact. Until that is worked out, a
  second edition would print translated prose around English row labels.

  **`docs/adr/0017` is the analysis and the recommendation, and it is proposed rather
  than accepted.** It measures the gap instead of estimating it: 1,205 of the artifact's
  6,582 leaves carry a string this repository wrote, 102 of them distinct, and 28 of
  those 102 reach `published/REPORT.md`. It reports what
  `wildfire_service_territory_overlap.artifact_diff` does with each option issue #56
  sketched, including that removing the labels costs the diff its keyed pairing on 72
  lists, and it recommends a fourth: the renderer names the row from the edition and the
  artifact keeps its English. Nothing in that document is decided and no code implements
  it. What did ship with it is the census, `catalog.artifact_prose` and
  `catalog.unclassified_string_fields`, which counts the strings and refuses a new
  string-valued field that nobody has classified as prose or as data.
- **Numbers use a hard-coded decimal point and no locale awareness, deliberately.** A
  reader whose locale writes `0,7%` will not see it written that way here. That is a
  decision rather than an oversight: one artifact writes every figure one way, so a
  number copied out of either edition is the same number, and `docs/adr/0016` records
  the reasoning. Measured against the standard's usual expectation of locale-aware
  formatting, this row is not met and is not intended to be.
