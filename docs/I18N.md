# Internationalization

**i18n status: Applies - deferred to the first release that renders this measurement for
a reader who is not reading the code.**

Reason: the internationalization standard is about civic data presented to the public,
and this project's output today is not that. It produces one JSON artifact and one
generated Markdown document, both aimed at somebody working directly with California
utility and wildfire data, and both read next to the source that produced them. There is
no user interface, no served page, no form, and no catalog. Localizing a technical
measurement document that nobody outside that audience reads would be motion rather than
access.

The trigger is a real one and not a date: if this measurement is ever rendered as a page
intended for a general reader, the audience changes and the standard binds immediately.
Recording it that way rather than declaring the standard inapplicable, because the
subject matter is squarely civic and the exemption is about the current form of the
output, not about the topic.

## What is not done

- Output strings are written in English, inline, in `src/wildfire_service_territory_overlap/report.py` and
  `src/wildfire_service_territory_overlap/measure.py`. There is no catalog and no extraction.
- No Spanish translation exists. If one is made it needs review by a native speaker
  rather than generation, and nothing here has had that.
- Numbers are formatted with a hard-coded decimal point and no locale awareness.
